THE MOST IMPORTANT ARCHITECTURE RULE: api.js
- No page script may read mockData.js or localStorage directly for application data. Every data operation goes through functions in api.js.
- Every api.js function must be ASYNC and return a Promise (use async/await with a short fake delay, e.g. 300ms, to simulate network). Return data in the same shape a real REST API would: { success: true, data: ... } or { success: false, message: "..." }.
- Name the functions after the future endpoints, and put the future endpoint in a comment above each one. Example comment: // Future: GET /api/products
- Required functions:
  Auth: registerUser(data), loginUser(email, password), logoutUser(), getCurrentUser()
  Products: getProducts({search, category, minPrice, maxPrice, sort, page}), getProductById(id), createProduct(data), updateProduct(id, data), deleteProduct(id)
  Categories: getCategories()
  Cart: getCart(), addToCart(productId, qty), updateCartItem(productId, qty), removeFromCart(productId), clearCart()
  Orders: placeOrder(orderData), getMyOrders(), getAllOrders() (admin)
  Profile: updateProfile(data)
- Persistence for mock mode: store users, cart, orders, current user and fake token in localStorage under clearly named keys (e.g. "ec_users", "ec_cart", "ec_orders", "ec_session"). Seed mockData into localStorage on first load only.
- Put a single constant at the top of api.js: const USE_MOCK = true; and a BASE_URL = "http://localhost:5000/api"; placeholder, so in Part 3 only this file changes.
- Passwords in mock mode are only for demo; add a comment that real hashing happens in the backend later.

ROUTE PROTECTION
- Write a helper in main.js: requireLogin() and requireRole(role). Call it at the top of protected pages. Unauthenticated users go to login.html with a redirect parameter.

FORM VALIDATION (client side, required on every form)
- Validate on submit AND on blur. Show a clear red error message under each invalid field, a green state for valid, and disable double-submission.
- Rules: required fields, email format, phone (10 digits), password min 8 characters with at least one letter and one number, confirm password match, pincode (6 digits), price > 0, stock >= 0 and integer, quantity within allowed range.
- Create a reusable validation helper (in main.js or a small section of auth.js) so rules are not copy-pasted.
- Use error messages that tell the user exactly what is wrong.

ERROR AND EDGE-CASE HANDLING
- Wrap api calls in try/catch. Show friendly messages with showToast, never raw errors or blank screens.
- Handle: empty states, out-of-stock products (disable Add to Cart), quantity above stock, corrupted localStorage (reset safely), missing image (fallback), invalid URL params.
- Escape/sanitize any user-entered text before inserting into the DOM (use textContent or an escape helper; avoid innerHTML with raw user input).
